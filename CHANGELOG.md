# Changelog

How Hoard grew from a planned idea into an app that deploys itself to Azure. Each section is one course milestone; numbers in brackets are the pull requests on [GitHub](https://github.com/El-Gibbor/Hoard/pulls?q=is%3Apr+is%3Amerged).

## Summative: The Complete DevOps Pipeline (2026-11-17 to 2026-11-18)

A merge to `main` now reaches a live, private Azure environment with no manual steps. Built as four pull requests into `feature/94-summative-pipeline` (#94): network and access (#99), database and registry (#102), configuration (#103), and delivery and docs (#104).

### Added
- **Remote Terraform state** (#99) in Azure Storage, created by `terraform/bootstrap.sh`, so the team and CD share one state (Entra ID access only, versioned).
- **Private network** (#99, #102): bastion, app and database subnets, each with its own NSG and an explicit deny for other VNet traffic.
- **Bastion host** (#99): the only SSH entry point, open to the admin's IP only.
- **Standard Load Balancer** (#99): serves the app on a public IP, probes `/healthz` and gives the private VM outbound access.
- **Azure Database for PostgreSQL Flexible Server** (#102): private access only, password generated by Terraform, connections over TLS.
- **Azure Container Registry** (#102): Basic tier with the admin user and anonymous pull off.
- **Least-privilege CD identity** (#102): Reader on the resource group, AcrPush, Network Contributor on the bastion NSG only.
- **`cd.yml`, Deploy to Production** (#104): on a merge to `main` it runs all of CI, builds and scans the images, pushes them to ACR by commit SHA, deploys with Ansible through the bastion and smoke-tests the public URL. It signs in to Azure with OIDC, so no cloud secret is stored. A manual run with an older SHA rolls back.
- **Docker log rotation** on the VM (#103).
- **npm audit allowlist** for advisories with no fix, each with a reason and a review date; the first entry is the `picomatch` ReDoS (#101).
- **README operations manual** (#104): architecture diagram, set-up from zero, runbook and health signals.

### Changed
- The app VM moved to a private subnet and lost its public IP (#99, #103). Ansible reaches it through the bastion with a `ProxyCommand` from the dynamic inventory.
- The database moved from a Postgres container on the VM to the managed server (#103). The `db` service and the vault's database password are gone.
- The VM pulls images from ACR with a short-lived token instead of from GitHub Container Registry (#103).
- `/api/health` now checks the database and returns `503` when it does not answer, so the probes and the smoke test catch a broken connection (#103).
- `ci.yml` can be called by CD, and no longer publishes to GHCR from `main` (#104).

### Removed
- `publish.yml`, replaced by `cd.yml` (#104).
- `moved.tf`. The Formative 3 single-VM layout is not carried over (#99).

## Formative 3: Infrastructure as Code and DevSecOps (2026-11-13 to 2026-11-14)

### Added
- Terraform for Azure: resource group, VNet, subnet, NSG and an Ubuntu VM with a static IP, with variables, outputs and a README (#72, #74, #75).
- Ansible roles: `common` (UFW, SSH hardening, fail2ban, unattended upgrades), `docker` (Engine and Compose from Docker's repository) and `app` (migrate, seed and start Hoard) (#76, #77, #78).
- Security scanning in CI: npm audit for both apps, Checkov for Terraform (#73), ansible-lint (#79) and Trivy for both images (#91). `SECURITY.md` records every finding and decision.
- A Publish workflow that pushes deployable images from `main` (#78).
- Azure deployment screenshots from each teammate (#83–#87, #89).

### Changed
- Terraform split into `network` and `compute` modules, with NSG rules generated by `for_each` (#92).
- The Ansible inventory became dynamic, read from `terraform output`, and the deploy steps gained `block` / `rescue` with clear failure messages (#93).
- Trivy findings fixed: npm removed from the API runtime image, base images bumped and pinned (#91).
- The playbook works on newer Ansible, the default VM size is one Azure has capacity for, and SSH is tighter (#88).

## Formative 2: CI Pipeline for a Containerised Application (2026-10-31)

### Added
- Multi-stage Dockerfiles for the API and for the frontend served by nginx, both running as non-root (#46, #47, #48).
- Docker Compose for the API, web app and Postgres, with health checks on every service (#49, #59).
- CI builds both images and publishes them to GitHub Container Registry on branch pushes, with npm and Docker layer caching (#51, #53).
- Branch protection requires every CI check before merging to `main` (#55).
- Docs for running with Compose and for the CI pipeline (#52, #54).

### Fixed
- Ownership tests check that the owner's expense exists before testing that another user cannot see it (#56).
